
# Docker
Docker is a platform used to package, deploy, and run applications inside containers. / You create an isolated environment for your application inside your computer.
Suppose you have a Python application:-
```
app.py
Python 3.12
Flask 3.0
requests
Other dependencies
```
Instead of manually installing everything on every server, you create a Docker image:
```
docker build -t my-python-app .
```
Then run it.
```
docker run my-python-app
```
Docker creates a **container** from that image.

```
VM: Virtualizes a complete machine
Docker: Isolates applications while sharing the host kernel
```
|VM| Docker |
|--|--|
| Virtual machine | Container |
|Has its own kernel|Shares host kernel|
|Heavier|Lighter|
|Strong OS-level isolation|Application/process-level isolation|


## 1. Docker Image & Containers
A **Docker Image is a packaged, read-only template used to create Docker containers.**
```
Docker Image
      ↓
   docker run
      ↓
Docker Container
```
**Example**
Suppose you have a Python application:
```
My Application
├── app.py
├── Python
├── Flask
└── Other dependencies
```
You package all the required things into an **image**:

```
┌─────────────────────────┐
│     Docker Image        │
│                         │
│  Application code       │
│  Python runtime         │
│  Flask                  │
│  Dependencies           │
│  Required files         │
└─────────────────────────┘
```

Then:

```
docker run my-python-app
```

Docker uses that image to create a **container**:

```
Docker Image
     │
     │ docker run
     ↓
┌──────────────────┐
│ Docker Container │
│                  │
│ Python App       │
│ Flask            │
│ Dependencies     │
└──────────────────┘
```

### Image vs Container
**Image = Template**
**Container = Running instance of that template**
For example:

```
             Docker Image
            "my-web-app"
                  │
       ┌──────────┼──────────┐
       ↓          ↓          ↓
 Container 1  Container 2  Container 3
```

You can create multiple containers from the same image.

## 2. Volumes
A **Docker volume is a way to permanently store data generated by a container.**
> What happens to my data when the container is deleted?

Suppose you run a MySQL container:
```
MySQL Container
└── Database
    ├── users
    ├── orders
    └── payments
```
Now you delete the container:
```
docker rm mysql-container
```
The container and its writable filesystem are gone.
So your database data can also be lost ❌.
That's where **volumes** come in.

## Volume
A volume stores data **outside the container's lifecycle**.
```
                 Docker
                   │
        ┌──────────┴──────────┐
        │                     │
   Container              Volume
        │                     │
   MySQL App  ─────────→  Database Data
```
Now:
```
docker rm mysql-container
```
The container is deleted, but:
```
Volume
└── Database Data
```
still exists ✅. You can create another MySQL container and attach the same volume.

## 3. Docker Networks
A **Docker network allows Docker containers to communicate with each other and with the outside world.**
Think of it like a **private network inside Docker**.
### Why do we need it?
Suppose you have a web application with 2 containers:
```
┌──────────────┐       ┌──────────────┐
│ Web Container│ ────→ │ DB Container │
│              │       │              │
│ Node.js      │       │ MySQL        │
└──────────────┘       └──────────────┘
```

The **Web container needs to communicate with the MySQL container**.

Docker Network connects them:
```
             Docker Network
        ┌─────────────────────┐
        │                     │
        │  Web ───────── DB   │
        │                     │
        └─────────────────────┘
```
## 4. Docker Registry & Docker Hub
A **Docker Registry is a place where Docker images are stored and distributed.** Think of it like a **warehouse for Docker images**.

**Docker Hub** is a public cloud-based Docker registry provided by Docker.

**Example:-**
Suppose you want to run `Nginx`.
You don't have to create the Nginx image yourself.
You can pull it from Docker Hub:
```
docker pull nginx
```
Docker downloads the image:
```
Docker Hub
    │
    │ docker pull nginx
    ↓
Your Server
    │
    ↓
nginx Image
```
Then:
```
docker run nginx
```
creates a container from that image.
```
Docker Hub
    ↓
nginx Image
    ↓
Docker Container
```

## 5. docker push
Suppose **you create your own application image**.
```
docker build -t myapp .
```
Now you want to store/share that image in a registry.
You push it:
```
docker push <username>/myapp
```
```
Your Machine
     │
     │ docker push
     ↓
Docker Hub
     │
     └── <username>/myapp
```
Another server can then download it:
```
docker pull <username>/myapp
```
## Image to Container Lifecycle
```
Dockerfile --> Built Image --> Docker Image --> Create Container --> Start Container --> Running Process

Running process :-
		1. Logs/Exec/Inspect
		2. Stop
			i. Restart
			ii. Remove Container
```
